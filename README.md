# 모노사파 키우기 — 두 자아의 믹스테이프

듀얼 자아 방치형 음악 성장 게임. 클릭으로 작업을 돕고, 일반·어둠 두 자아로 곡을 만들고, 앨범과 공연으로 성장한다.
기획서(`monosapa_game_design.md`) 기준 MVP 전체(14장 1~4단계)를 구현한 웹게임이다. 게임 규칙은 모두 클라이언트에 있고, 서버(NestJS + MongoDB)에는 구글 로그인, 계정별 저장, 계정 레벨 랭킹, 공개 챗방, 문의함이 있다.

> 게임 속 가상의 설정·대사·댓글이며 실제 인물의 건강 상태나 성격, 발언을 나타내지 않는다. 일반속성 싱글 제목은 제작자가 지정한 목록(`frontend/src/game/content.ts`의 `SINGLE_TITLES.normal`)을 순서대로 쓴다. 곡 발매는 게임 안의 연출이고 실제 음원은 만들어지지 않는다.

## 구조와 실행

npm workspaces 모노레포다.

```text
frontend/   React + TypeScript + Vite 게임 클라이언트 (게임 규칙·UI·테스트·시뮬레이션 전부)
backend/    NestJS + TypeScript 서버 (health, 구글 로그인 auth, 계정 users, MongoDB 연결 database). 게임은 아직 서버에 저장하지 않는다. 기능별 모듈 구조: src/{health,users,auth}/{*.module,*.controller,*.service,*.schema,dto/}, src/database, src/config/{app.config,config.module}.ts, src/app.module.ts, src/main.ts
```

```bash
npm install          # 루트에서 한 번
npm run dev          # 게임 http://localhost:5173 (백엔드 없이도 동작)
npm run dev:backend  # (선택) NestJS http://localhost:3000/api/health
npm test             # 자동 테스트 615개 (엔진·저장·미니게임·새 기능·콘텐츠 팩 2·화면 렌더링)
npm run typecheck
npm run build        # frontend/dist, backend/dist
npm run sim          # 성장 속도 시뮬레이션
```

Node 22 + npm 11에서 확인했다. 게임은 외부 API·원곡·로그인 없이 동작하며 저장은 브라우저 localStorage다. 개발 서버의 `/api` 요청은 backend(3000)로 프록시된다.

### 구글 로그인 + MongoDB 설정

로그인은 설정 창(⚙)의 「계정」에 나온다. 서버에 `GOOGLE_CLIENT_ID`가 없거나 서버에 닿지 않으면 계정 영역은 아예 숨겨지고 게임은 그대로 동작한다.

1. Google Cloud Console → API 및 서비스 → 사용자 인증 정보 → **OAuth 클라이언트 ID(웹 애플리케이션)** 를 만들고, *승인된 JavaScript 원본*에 `https://monogame69.net`(개발은 `http://localhost:5173`)을 넣는다. 리디렉션 URI는 필요 없다(ID 토큰 방식).
2. 서버에 MongoDB를 준비하고(로컬 mongod 또는 Atlas) pm2 환경에 넣는다:

```bash
MONGODB_URI='mongodb://127.0.0.1:27017/monosapa' GOOGLE_CLIENT_ID='<클라이언트 ID>' pm2 restart monosapa-backend --update-env && pm2 save
```

- DB에는 `users`(구글 `sub` 유니크, 이메일·이름·사진), `sessions`(토큰 SHA-256 해시, 만료되면 TTL 인덱스가 삭제), `saves`(계정별 게임 저장), `chat_messages`(챗방, 14일 TTL), `inquiries`(문의와 답변) 컬렉션이 생긴다.
- **관리자**: 서버 환경 변수 `ADMIN_EMAILS`(쉼표로 구분, 구글에서 확인된 이메일과 비교)에 든 계정이 문의 답변과 챗방 메시지 삭제를 할 수 있다. 비어 있으면 관리자가 없다. `backend/.env`에 `ADMIN_EMAILS=내이메일@example.com`을 넣고 `pm2 restart monosapa-backend --update-env`.
- 로그인 요청은 클라이언트 ID(aud)·서명·만료가 맞는 구글 ID 토큰만 받는다. 세션 쿠키는 HttpOnly·SameSite=Lax이고 nginx 뒤 https에서는 Secure다(`trust proxy`).
- 검증 방법: 메모리 MongoDB(실제 mongod 8.2)로 로그인·재로그인·만료·위조 쿠키·로그아웃 등 22개 시나리오를 HTTP로 확인했다(구글 검증만 대역). 화면은 브라우저에서 직접 확인하지 못했다.

### 배포 (nginx + pm2)

```bash
./deploy.sh              # 테스트 → 빌드 → 백업 → 웹 루트 교체 → (백엔드가 바뀌었으면) pm2 재시작 → 검증
./deploy.sh --dry-run    # 빌드만 하고 바뀔 파일을 보여 준다 (서버는 건드리지 않는다)
./deploy.sh rollback     # 프런트를 가장 최근 백업으로 되돌린다
```

- 프런트(`frontend/dist`)는 nginx 웹 루트 `/var/www/monosapa`에 `assets/` 먼저, `index.html` 마지막 순서로 올린다. 내용(체크섬)이 같은 파일은 다시 복사하지 않는다. 교체 전 `~/deploy-backup/monosapa-<시각>`에 백업하고 최근 10개만 남긴다.
- 백엔드는 `backend/dist`가 바뀌었거나 pm2 프로세스(`monosapa-backend`)가 꺼져 있을 때만 `pm2 restart` 후 `pm2 save`한다. 서버에 저장 상태가 없어 재시작해도 잃는 것은 없다.
- 마지막에 `https://monogame69.net`이 새 번들을 서비스하는지와 `/api/health`를 확인하고, 실패하면 롤백 명령을 안내하며 종료 코드 1로 끝난다.
- nginx 설정(SSL·`/api` 프록시)은 스크립트가 관리하지 않는다. `rollback`은 프런트만 되돌리고 백엔드는 되돌리지 않는다. 커밋하지 않은 변경도 작업 폴더 그대로 배포되므로 경고만 띄운다. 경로·도메인·프로세스 이름은 환경 변수(`WEB_ROOT`, `DOMAIN`, `PM2_NAME`, `BACKUP_ROOT`, `KEEP_BACKUPS`)로 바꾼다.

> 참고: backend의 Nest CLI 의존성 일부가 Node ≥ 22.22를 요구해 Node 22.15에서는 설치 시 EBADENGINE 경고가 나온다(빌드·실행은 정상).

## 구현한 것

- **두 자아**: 일반/어둠 전환(무료, 3초 재전환 잠금), 과열 G 0~100, 80 이상 고속 구간, G=100 「마이크 압수」(일반 자동 전환, 20초 생산 50%, 재진입은 20초 경과 + G≤60). 재화는 잃지 않는다.
- **생산·수입**: 자동 라임(일반/어둠 별도 보관), 작업하기 패드(터치·마우스·키보드 합산 초당 3회 상한, 누르고 있으면 초당 2회), 팬 기반 인세, 레벨.
- **싱글·앨범**: 제목 미리보기·필요 라임·보상 표시, 즉시 발매, 가상 댓글. 앨범은 싱글을 고르는 방식이 아니라 **정해진 묶음(`ALBUM_CATALOG`)을 속성마다 따로 위에서부터 차례로 발매**한다(싱글처럼 일반·어둠이 서로 기다리지 않고, 코인만 있으면 지금 자아와 상관없이 낸다; 발매 탭에 두 속성의 다음 앨범이 각각 나온다). **일반 6장**: ① [SAPA] EP(5곡) → ② [MONO] EP(5곡, 타이틀 「이리 와」) → ③ [cybergirl.vst3] 싱글(3곡, 타이틀 「cybergirl.vst3」) → ④ [Voyage, Love & Blank] 정규(11곡) → ⑤ [why my *GIRLS* not stereo] EP(7곡) → ⑥ [why my *GIRL* not mono] 싱글(2곡). **어둠 3장**: ① [...정병러브...] EP(3곡, 타이틀 「정신병자러브」) → ② [니엄마는...] EP(3곡) → ③ [트롯사파 팩] EP(2곡). 비용 10,000 → 350,000 → 20,000,000 → **1,000,000,000 → 50,000,000,000 → 2,500,000,000,000**코인, 팬 +100 → +200 → +300 → **+400 → +500 → +600**(일반 1~3번째는 사용자 지정 값, 일반 4~6번째는 같은 흐름으로 이은 제안값. 어둠 1~3번째는 사용자 지정 값으로 비용 100,000 → 6,900,000 → 740,000,000코인, 팬 +124 → +300 → +740, 인세 +12% → +24% → +40%, 발매 다이아 💎100 · 200 · 400이다. `balance.ts`의 `album`·`royalty.perAlbum`·`diamond.album`은 속성별로 나뉜다), 발매 시 인세 배율 +8% → +10% → +12% → **+14% → +16% → +18%**(속성마다 낸 장수만큼 합산하고 일반·어둠 두 자아의 인세에 모두 곱해진다: 일반 3장 ×1.30, 일반 6장 ×1.78, 어둠 3장까지 모두 ×2.54). 듀얼 앨범 기능은 없앴다. 속성별로 모두 내면 그 속성은 더 낼 수 없고, 도감에 수록곡과 함께 속성별로 보관된다.
- **장비 3종**(마이크·작업실·홍보, 최대 20레벨): 구매 전·후 생산/수입 표시, 작업실 5레벨마다 방 외형 변화. **장비는 속성마다 따로 있고(사용자 지정) 그 속성일 때만 효과가 난다.** 장비 탭에서 「일반속성 장비 / 어둠속성 장비」를 전환해 산다. 레벨당 효과는 같고, 어둠 장비는 최초 비용이 일반의 12배, 가격이 늘어나는 폭(성장률 − 1)이 일반의 2.4배다. 방 외형 단계는 지금 자아의 작업실 레벨을 따른다.
- **클릭 업그레이드**(장비 탭, 사용자 요청으로 추가): 코인으로 올리며 **레벨당 작업하기 한 번에 얻는 기본 라임 +1**(그 속성의 생산배율이 곱해진다). 일반속성은 **순수 음악력**(비용 `ceil(250×1.5^레벨)`: 250 → 375 → 563 …), 어둠속성은 **음지 드립력**(비용 `ceil(3000×2.2^레벨)`)이고 각자 자기 속성에서만 효과가 난다. 최대 레벨은 없고 자동 생산(초당 라임)에는 영향이 없다. 값은 `balance.ts`의 `musicPower`·`dripPower`. 예전 저장에는 이 필드들이 없어 0레벨로 읽는다.
- **공연 8곳(+비밀 공연장 3곳)**(방구석 → 지하 클럽 → 소형 공연장 → 단콘 → 중형 공연장 → 중대형 공연장 → 대형 콘서트 → 월클 콘서트): 팬 조건 + 이전 공연장 클리어로 해금, 자동 공연(1배, 클리어 인정), 직접 공연(방구석은 마이크 타이밍, 지하 클럽은 모노사파런, 소형 공연장은 무대 세팅 블록, 단콘은 응원봉 머지 웨이브, 중형 공연장은 음파 튕기기, 중대형 공연장은 돌발 사고 막기, 대형 콘서트는 무대 서바이버, 월클 콘서트는 월드투어 인크리멘탈, 비밀 공연장은 폐건물 지하공연이 정전 속 박자·다크웹 라이브공연이 후원 채팅 스와이프·저세상 공연페스티벌이 삼도천 징검다리), 공연장별 120초 쿨다운, 첫 클리어 보너스 1회, 소형 공연장 첫 클리어 시 「첫 투어 완료」 카드(그 뒤 5곳은 확장 콘텐츠). 새 5곳 수치는 팬 3,000/8,000/20,000/50,000/150,000명, 기본 코인 300/600/1,200/2,500/6,000, 첫 클리어 보너스 3,000/7,500/18,000/45,000/120,000(`STAGES`). 직접 공연 난이도는 월클 콘서트가 ×2.53.
- **모노사파런(지하 클럽의 직접 공연)**: 달리면서 점점 빨라지는 러너. 탭·스페이스·↑로 점프(공중에서 한 번 더), 장애물(스피커 박스)에 부딪히면 하트 3개 중 1개를 잃고 1.2초 무적(그동안 속도 ×0.7), 하트가 0이 되면 실패. **완주하면 성공**, 점수(0~1000)는 코스에 깔린 젤리 중 먹은 비율이고 보상 공식은 타이밍과 같다(`기본 코인×(1+점수/1000)×자아 배율`, 실패는 ×0.5·첫 클리어 아님). **지하 클럽: 일반 400m / 어둠 697.4m**(사용자 요청으로 짧아진 대신 훨씬 빨라진다). 어둠은 더 빠르고 더 길며 **보상이 일반의 4배**(`run.persona.dark.rewardMult`). 속도는 달린 거리에 비례해 일반 8→20, 어둠 11→28(u/s)로 선형 증가(시작의 2.5배)하고 장애물 간격은 반응 시간(초) 기준이라 뒤로 갈수록 촘촘해진다. 스크롤 단위(u)로 규칙을 돌리고 화면의 m는 코스 길이에 비례해 환산한다(일반 900u=400m, 어둠 1,570u=697.4m). 달리는 동안 거리는 정수로 올라가고 결승선에서 목표 거리가 된다. 코스는 공연장마다 정한다(`run.stageCourse`, 없는 공연장은 `run.persona`의 원래 코스): 코스 설정이 없는 공연장(지금은 쓰는 공연장 없음, 예전에는 비밀 공연장 폐건물 지하)은 원래 코스 일반 2,600m·어둠 6,900m(일반 1,500u 8→16, 어둠 2,400u 11→22)를 그대로 쓴다. 코스는 시드 난수로 만들어 같은 시드면 같은 코스, 규칙은 `game/runner.ts`(React 비의존)에 있고 화면은 `screens/RunStage.tsx`. 알맞게 점프하는 자동 플레이어 기준 지하 클럽 완주 약 69초(일반)/86초(어둠)(원래 코스 약 130초/151초), 젤리 약 68~77%이고, 점프 타이밍이 ±0.1초 흔들려도 원래 일반 코스보다 피격이 적다(시드 40개 평균: 일반 0.55번 · 어둠 0번 vs 원래 일반 1.52번). 직접 공연 중 탭을 숨기면 일시정지한다.
- **무대 세팅 블록(소형 공연장의 직접 공연, 사용자 요청으로 추가)**: 「블록 블라스트」처럼 8×8 무대 바닥에 악기 블록 3개를 끌어다 놓고(회전 없음, 작은 점부터 3×3·5칸 막대까지 34가지) 가로·세로 한 줄을 채우면 합주가 터지는 게임. 손의 3개를 다 놓으면 새 3개를 받고, 새 블록은 지금 바닥에 하나씩은 들어가는 것만 나온다. 공연은 곡 4개(마지막이 앙코르) × 곡당 23초 = 92초이고 곡마다 점수 배율이 ×1 → ×1.15 → ×1.3 → ×1.5로 오른다. **점수(점)** = (놓은 칸 수 × 1 + 10 × n(n+1)/2 × 콤보 배율) × 곡 배율(n = 한 번에 터뜨린 줄 수, 가로+세로 합. 4줄이면 100). 콤보는 줄을 터뜨린 수가 이어진 횟수이고 못 터뜨린 수가 3번째가 되면 끊기며, 배율은 1 + 0.25 × (콤보 − 1)(최대 +100%). 바닥이 통째로 비면 +60. **무대 사고**: 곡이 바뀔 때마다 불량 칸이 생긴다(일반 0·1·1·2칸 = 고장 난 장비, 어둠은 시작할 때 3칸 + 0·1·2·2칸 = 던져진 물건). 불량 칸은 찬 칸으로 치지만 지우기 전에는 못 놓고, 그 칸이 낀 줄이 터지면 같이 사라진다. 블록은 곡마다 정해진 가중치로 뽑고(작은 것·중간·큰 것, 뒤 곡일수록 어려운 블록이 늘고 어둠은 같은 곡에서 한 단계 더 어렵다) 놓을 곳이 하나도 없으면 스태프가 가장 찬 가로줄·세로줄을 치우고 새 블록을 준다(한 판에 1번). 그 뒤에도 막히면 공연이 거기서 끝난다. **열기 점수** = 1000 × min(1, 점수 ÷ target)(일반 480, 어둠 750)이고 **600 이상이 클리어**(일반 288점, 어둠 450점). 보상은 타이밍과 같은 공식에 **어둠 ×2**(`blocks.persona.dark.rewardMult`). 조작은 블록을 끌어서 놓기(마우스·터치, 터치는 손가락에 가려지지 않게 블록이 1.8칸 위에 뜬다)이고 놓을 자리와 터질 줄이 미리 보인다. 규칙은 `game/blocks.ts`(React 비의존, 시드 난수), 화면은 `screens/BlockStage.tsx`. 봇 시뮬레이션(시드 300개, 휴리스틱 봇이 한 수에 걸리는 시간을 바꿔 가며): 한 수에 1.8초 걸리는 숙련 봇은 일반 96%·어둠 83% 클리어, 2.5초는 일반 94%·어둠 41%, 3.5초에 실수가 섞이면 일반 20%·어둠 0%, 5초는 둘 다 0%, 아무 데나 놓는 봇은 일반 16%·어둠 0%, 가만히 있으면 0점. 숙련 봇은 한 판에 35~49개를 놓는다. jsdom으로 끌어서 놓기·겹침 표시·터치 띄우기·곡 진행·끝 안내까지 확인했지만 실제 브라우저와 모바일 터치 감각, 사람의 실제 난이도는 측정하지 못했다. 소형 공연장은 새 게임을 해 보도록 **임시로 팬 1,200명·지하 클럽 클리어 조건 없이 입장**할 수 있다(`TEMP_OPEN_STAGES`, 비우면 원래 조건). 단콘·중형·중대형·대형·월클도 같은 목록에 들어 있다.
- **응원봉 머지 웨이브(단콘의 직접 공연, 사용자 요청으로 추가)**: 5×5 무대의 응원봉을 합쳐 곡마다 열기 목표를 채우고, 곡 사이에 이펙터를 골라 빌드를 키우는 머지 로그라이트. 응원봉은 색 3가지 × 단계 1~4이고, 같은 색·같은 단계가 상하좌우로 3개 이상 붙어 있으면(깜박여서 알려 준다) 그중 하나를 눌러 합친다. 누른 칸에 한 단계 높은 응원봉이 생기고 나머지 칸은 새 1단계 응원봉(무작위 색)으로 다시 채워지며, **5개 이상 묶음은 두 단계를 뛰어오른다**. 4단계를 합치면 별 응원봉이 되어 터진다. **응원 파워** = 합쳐서 나온 단계별 기본 파워(2단계 10 · 3단계 36 · 4단계 130 · 별 480) × 묶음 크기 ÷ 3 × 콤보 배율 × 앰프 배율. 콤보는 직전 합치기에서 2.5초 안에 또 합치면 이어져 배율이 +10%씩(최대 +50%) 오르고 합칠 수 없는 곳을 누르면 끊긴다. **연쇄**: 합쳐서 생긴 응원봉이 같은 색·같은 단계 3개 이상과 붙게 되면 저절로 이어서 합쳐지고(최대 6번) k번째 연쇄는 파워 × (1 + 0.5k)다. 공연은 곡 4개(마지막이 앙코르) × 23초이고 곡마다 **열기 목표**(일반 720·565·550·550, 어둠 840·685·770·815)가 있어서 그 곡에서 모은 파워 ÷ 목표(상한 1)만큼 250점씩 받는다. **열기 점수 600 이상이 클리어**, 보상은 타이밍과 같은 공식에 **어둠 ×2**(`merge.persona.dark.rewardMult`). **이펙터**: 앙코르를 뺀 곡이 끝나면 시간이 멈추고 후보 3개 중 하나를 고른다(겹쳐 고를 수 있고 한도 3겹, 작은 합창은 1번). 🔊 앰프(파워 +20%) · 💡 조명(이후 곡마다 +3초) · 🎶 코러스(새 응원봉이 25% 확률로 2단계) · ⛓️ 체인 증폭기(연쇄 보너스 +0.5) · 🤝 작은 합창(2개만 붙어도 합침, 파워 ×0.6). **야유꾼(어둠)**: 새로 채워질 때 🗯 야유꾼이 곡마다 6·10·14·18% 확률로 섞여 나온다(판 위 최대 5명). 합칠 수 없는 칸이고, 합친 묶음 옆에 있으면 사라지며 파워 6을 준다. 판 위에 있는 동안은 합치기 파워가 한 명당 7% 줄어든다. 합칠 수 있는 묶음이 없어지면 1단계 응원봉의 색을 다시 섞고 그래도 없으면 이어진 세 칸을 1단계로 바꿔서 항상 한 수는 남는다. 조작은 응원봉 누르기(마우스·터치·키보드 Enter)이고 합칠 수 있는 응원봉이 깜박인다. 규칙은 `game/merge.ts`(React 비의존, 시드 난수), 화면은 `screens/MergeStage.tsx`. 봇 시뮬레이션(시드 200개, 가장 값진 묶음을 누르는 봇이 한 번 누르는 데 걸리는 시간을 바꿔 가며): 1.2초 숙련 봇은 일반·어둠 100% 클리어, 1.8초는 일반 85%·어둠 63%, 2.8초는 일반 9%·어둠 1%, 아무 묶음이나 1.8초마다 누르는 봇은 일반 30%·어둠 7%, 가만히 있으면 0점. 이펙터는 어느 하나가 압도하지 않는다(무작위로 골라도 일반 86%·어둠 46%). 처음 목표(일반 600·470·460·460, 어둠 700·570·640·680)에서는 1.8초 봇이 일반 98%·어둠 92%라 너무 쉽다는 의견으로 1.2배 올렸다. jsdom으로 누르기·합치기·이펙터 고르기·곡 진행·끝 안내까지 확인했지만 실제 브라우저와 모바일 터치 감각, 사람의 실제 난이도는 측정하지 못했다.

  - **해시태그 챌린지**(서버): 주마다 돌아가는 주제(`#새벽감성` 등 12개)에 한 줄(60자)을 올린다(한국 시간 월요일 0시 기준, 주에 한 줄). 좋아요(자기 글 제외)·신고 3회면 숨김·본인/관리자 삭제. 지난주 결과는 1위 💎10 · 2위 6 · 3위 4 · 참가 1(+좋아요 5개마다 1, 최대 +5)로 서버가 한 번만 계산해 주고, 3위 안의 글은 **가사 노트**에 남는다. 지난 8주의 1위는 명예의 전당.
  - **실시간 음원 차트**(서버): **일반속성 곡 전체 목록과 어둠속성 곡 전체 목록**으로만 이뤄진다(NPC 곡 없음, 사람당 곡 수 제한 없음). 모든 계정이 발매한 싱글이 그 곡의 속성 목록에서 각각 순위를 겨루고, 화면에서 「일반 / 어둠」 탭으로 넘겨 본다(50곡씩 더 보기, 한 목록 응답은 위쪽 1,000곡까지). 점수 = √팬 × 신선도 × 시간별 잡음, 곡마다 하루 4% 확률로 **역주행**(×4). 1분 캐시, 지난 시간 대비 순위 변화 표시. 내 곡이 두 목록을 통틀어 10위 안이면 하루 한 번 💎(1위 5 · 3위 안 3 · 10위 안 1). 경쟁 상대가 사람뿐이라 곡을 낸 사람이 적을 때는 쉽게 1위가 된다.
  - **Wrapped**(더보기 → 결산): 기록에서만 계산한 슬라이드 10장(작업하기·더 오래 쓴 자아·곡·팬·압수·가장 많이 답장한 팬·모노그램·수집·아케이드·업적)과 공유 카드. 카드는 캔버스로 이 기기에서 만들어 공유 시트나 파일로 내보내며 어디에도 올라가지 않는다. 올해만 따로 센 기록은 없어서 "플레이를 시작한 뒤 지금까지"의 결산이다.
  - **내 목소리 샘플러**(더보기 → 목소리 샘플러): 마이크로 3초를 녹음(앞뒤 무음 자르기·정규화)해 패드 4개(음높이 ×0.75/1/1.25/1.5)와 8스텝 비트로 쓰고, 「작업하기 효과음으로 쓰기」를 켤 수 있다. 녹음은 IndexedDB·설정은 localStorage에만 있고 서버·게임 저장에는 올라가지 않는다.
  - **계단 랭킹**(더보기 → 랭킹 → 「무한의 계단」 탭, 서버): 무한의 계단 **역대 최고 클리어 층** 순위(상위 20명 + 내 순위). 저장할 때 서버가 `state.arcade.tower.best`에서 `towerBest`를 뽑아 `saves`에 같이 저장하고 `{towerBest}` 인덱스로 정렬한다(상한 100만, 이상한 값은 0). 같은 층이면 먼저 가입한 쪽이 앞서고, 한 층도 못 깬 계정은 오르지 않는다. 이름·사진은 구글 계정 것이고 이메일은 내려주지 않는다. 주간(이번 주 층) 순위는 주 경계가 기기 시간대라 서버와 맞지 않아 두지 않았다. 조작된 저장은 막지 못한다.
- **챗방**(더보기 → 챗방): 로그인한 모든 사람이 쓰는 공개 자유 채팅. 3초마다 최근 60개를 새로 불러온다. 이름·사진은 구글 계정 것이 그대로 보이고 달고 있는 칭호가 붙는다. 200자, 연속 전송 1.5초 간격 · 분당 20개 · 같은 말 10초 반복 금지(서버가 막는다). 내 메시지는 지울 수 있고 관리자는 모두 지울 수 있다. 14일 뒤 자동으로 사라진다.
- **문의함**(더보기 → 문의함): 종류(버그/제안/계정·저장/기타) · 제목 50자 · 내용 1000자로 문의를 보내고(시간당 3건, 대기 10건 상한), 「내 문의」에서 답변을 본다. 구글 이름과 이메일이 함께 저장돼 관리자가 확인한다. **관리자 계정**(서버 환경 변수 `ADMIN_EMAILS`에 든 이메일)이면 「관리자」 탭에서 모든 문의를 보고 답변한다.
- **스트리밍 통계**(사용자 요청으로 추가, 통계 탭 📊). 수치는 `balance.ts`의 `streaming`.
  - 팬이 있으면 **팬 1명당 초당 0.2**(초당 팬 수 × 0.2)만큼 스트리밍이 실제 경과 시간에 따라 쌓인다(자아·장비·과열과 무관, 오프라인은 다른 생산처럼 효율 70%·최대 2시간). 쌓인 스트리밍은 **Spotify · YT Music · Melon · Apple Music**에 무작위로 나뉘어 플랫폼별로 기록된다. 화면에는 K·M 약어나 소수 없이 **1회 단위 정수**로 표시한다(`components/format.ts`의 `fmtStreams`, 초당 값이 1 미만이면 '1 미만').
  - 분배는 10분 구간마다 새로 뽑는 무작위 비율이고(`shareBucketMs`), 저장된 씨앗과 구간 번호만으로 정해지는 시드 난수라 엔진은 순수 함수로 남는다. 한 번에 크게 전진해도(오프라인 정산) 여러 번 나눠 전진해도(온라인 틱) 플랫폼별 결과가 같다. 구간마다는 크게 쏠리기도 하지만 오래 쌓이면 각 플랫폼이 25%에 가까워진다.
  - **1시간마다 코인으로 정산**할 수 있다(통계 탭 버튼, **30스트리밍 = 1코인**). 30으로 나누고 남은 스트리밍은 다음 정산으로 넘어가고, 정산하지 않아도 사라지지 않는다. 누적 기록은 정산해도 줄지 않는다. 첫 정산은 새 게임 시작 후 1시간 뒤다.
  - **유통사 호감도**(사용자 요청, 통계 탭의 정산 카드 아래): 코인으로 올리는 스트리밍 수익 업그레이드. **레벨당 정산 코인 +5%**(레벨끼리 더해져 Lv.10이면 ×1.5), 비용은 **첫 5,000코인, 이후 1.4배씩**(`ceil(5000 × 1.4^레벨)`), 최대 레벨은 없다. 쌓이는 스트리밍 수와 누적 기록은 그대로고 코인으로 바꾸는 비율만 `30 ÷ 배율`스트리밍 = 1코인으로 바뀐다(남은 스트리밍은 그대로 다음 정산으로 넘어간다). 수치는 `balance.ts`의 `distributor`, 레벨은 저장의 `distributor`(없는 예전 저장은 0레벨). 올리면 구매 1회로 센다.
  - 스트리밍이 없던 예전 저장은 0에서 시작하고 첫 정산은 바로 가능하다(복귀 정산분만 쌓여 있다). 기기 시계가 거꾸로 가도 정산 간격은 1시간보다 길어지지 않는다.
- **화면**: 모바일 세로 우선(360px 확인), 버튼 최소 44px, 모션 감소, 캐릭터 이미지 2종(frontend/public/assets, 없으면 임시 SVG로 대체)·임시 SVG 작업실, 선택 음향(첫 입력 후에만 켜짐, 음소거 설정).

- **스트리밍 정산을 넣은 뒤의 수치다(괄호는 정산 없이 돌린 이전 값, `npm run sim -- --no-streaming`).** 봇은 정산 간격(1시간)이 지나는 즉시 정산한다. 첫 앨범은 약 5~8% 앞당겨졌고(예: 클릭 2회/초·혼합 253분 → 237분, 팬당 초당 0.85였을 때는 14~26%), 첫 발매·방구석처럼 1시간 안에 끝나는 구간은 거의 그대로다. 스트리밍은 팬 수에 비례해 쌓이므로 팬이 많아질수록 비중이 커진다: 처음 지정값(3스트리밍 = 1코인)은 팬당 초당 0.283코인으로 인세의 11배라 30으로 바꿨고, 이후 팬당 초당 스트리밍을 0.85에서 0.2로 낮춰 지금은 팬 1명당 초당 약 0.0067코인(= 0.2 ÷ 30)으로 인세 기본치(팬당 초당 0.025)의 약 27%다.
- **장비를 속성별로 나눈 뒤의 수치다.** 일반 장비는 일반속성에서만, 어둠 장비는 어둠속성에서만 효과가 나고 어둠 장비는 가격이 12배·성장 폭이 2.4배라 어둠을 쓰는 경로는 첫 앨범·지하 클럽이 늦어졌다. 일반만 쓰는 경로는 그대로다. 봇은 어둠을 쓰는 전략일 때 어둠 장비도 가장 싼 것부터 사지만, 순수 음악력과 음지 드립력은 사지 않는다.
- 싱글 공식을 `ceil(130×3.3^n)` / `floor(50×1.44^n)` / `ceil(5×1.8^n)`으로 바꾼 뒤의 결과다. 싱글 비용이 곡마다 3.3배씩 뛰어 6시간 동안 6~12곡에서 멈추고, 앨범은 지정한 카탈로그뿐이고 팬 +100/+200/+300(이후 +400~+600)은 비싼 코인(1만/35만/2천만, 이후 10억·500억·2.5조)이 필요해서, 앨범은 초반 지름길이 아니라 중후반 코인 소비처다. 팬 대부분은 싱글에서 나온다.
- **투어 완료 시간은 더 이상 목표가 아니다.** 사용자 결정으로 이 게임은 "첫 투어를 빨리 끝내는 것"이 아니라 계속 키워 나가는 게임이다(기획서의 1~2시간 투어·「일반만으로도 모든 기본 지역 개방」 목표는 접었다). 위 표는 현재 수치의 참고용이다. 첫 앨범(10,000코인)은 방치로 3시간대에 낼 수 있다.
- **싱글 비용·효과는 자아별로 따로 센다**(n은 그 자아로 낸 싱글 수). 어둠을 함께 쓰면 두 줄의 곡선을 동시에 타서 첫 발매는 빨라지지만, 어둠 장비가 비싸고 일반 장비는 어둠에서 효과가 없어서 이후에는 일반만 쓸 때보다 느려질 수 있다.
- 이 봇은 구매·발매를 놓치지 않는 이상적인 플레이어라서, 실제 플레이는 이보다 느릴 수 있다.

## 모호한 규칙에 내린 작은 결정

- **시각 체계**: 모든 시각은 `Date.now()` 기준 ms. 엔진의 "지금"은 `state.lastSettledAt`이고, 명령은 매번 정산 후 실행한다.
- **마이크 압수 잠금**: 별도 잠금 타이머 없이 「20초 경과 + G≤60」 재진입 조건 자체가 잠금이다. 이 조건은 어둠 재진입에 성공하면 해소된다. 압수 직후 일반으로 돌아가는 것은 막지 않는다(이미 일반).
- **어둠 수동 전환**: G≤80(80 포함)이면 허용. 압수 후 재진입은 G≤60.
- **오프라인 2시간 초과분**: 앞쪽 2시간만 효율 70%로 지급하고, 나머지 시간은 지급 없이 과열 회복·잠금만 실시간 100%로 흘려보낸다.
- **탭 숨김 복귀**: 숨긴 시간이 짧아도 오프라인 효율(70%)로 한 번 정산한다. 결과창은 30초 이상일 때만 띄운다(보상은 항상 반영). 온라인 틱 간격이 5초를 넘으면(절전 복귀 등) 오프라인으로 본다.
- **입력 상한**: 1초 슬라이딩 창 안에 3회. 누르기 유지는 0.5초 간격(초당 2회). `onClick`을 쓰지 않고 포인터·키 다운만 받아 탭+길게누르기 이중 지급이 없다.
- **싱글 제목**: 자아별 목록에서 결정적으로 고르고(미리보기와 동일), 같은 제목이 다시 나오면 `(2)`를 붙인다. ID는 `single-N`로 제목과 분리.
- **앨범 속성**: 일반 6장·어둠 3장이고, 속성(`content.ts`의 `ALBUM_CATALOG[].type`)마다 따로 순서대로 발매한다(`albumSeries`). 속성은 순서·표시에만 쓰고 보너스 효과는 같다(어느 속성의 앨범이든 두 자아의 인세에 곱해진다). 듀얼 앨범과 팬 ×1.25 보너스는 사용자 요청으로 삭제했다. 앨범은 발매한 싱글과 무관하고, 저장에는 id·발매 시각만 쓰며 제목·속성은 카탈로그에서 id로 찾아 읽는다(어둠 앨범이 생기면서 위치가 아니라 id로 복원한다). 모르는 id·겹친 id·예전 저장(싱글 2개 앨범)은 아직 안 낸 일반 앨범을 앞에서부터 채워 옮겨 읽고, 자리가 없으면 버린다.
- **자아별 번호와 비용**: 싱글 번호와 도감 목록은 일반/어둠별로 따로 센다. 싱글 발매 비용·효과(필요 라임·코인·팬)의 n도 자아별이라, 일반을 11곡 낸 뒤 처음 어둠으로 내면 어둠 첫 곡 값(필요 라임 50 등)이다. 두 자아의 성장 곡선은 `frontend/src/game/balance.ts`의 `single.normal`/`single.dark`에서 따로 조정한다. 인세의 앨범 수와 앨범 비용·팬은 발매한 앨범 수 기준이다. 싱글 내부 ID(`single-N`)는 전체 순서이고 앨범 ID는 일반 `album-1~6`, 어둠 `album-dark-1~3`이다.
- **공연**: 직접 공연의 600점 미만 보상은 `floor(계산값×0.5)`. 자동 공연은 자아와 무관하게 기본 코인 1배. 직접 공연 시작 시 쿨다운과 공연 자아를 확정하고 즉시 저장한다. 새로고침하면 진행 중 공연은 포기로 처리되며 쿨다운은 유지된다. 시작 전 3초 카운트다운은 미니게임 시계에 포함되지 않는다.
- **불러오기**: 가져온 파일의 `lastSettledAt`은 현재로 맞춘다. 오래된 파일을 반복해서 불러와 오프라인 보상을 다시 받을 수 없다.
- **대사 톤**: 기본은 「원래 톤」. 「순화」는 욕설이 들어간 어둠 대사만 같은 뜻의 순한 말로 바꾼다(수치 동일).
- **자동 말풍선**: 직전 말풍선 이후 15초 미만이면 나오지 않는다. 발매·구매·압수·공연 같은 이벤트 대사는 즉시 우선한다.

## 남은 제약

- 코인은 장비·앨범·간식·홍보 캠페인에 쓰인다. 간식과 캠페인은 가격이 플레이어 레벨에 따라 올라 후반에도 싱크로 남지만, 환생·새 믹스테이프는 기획서 범위 밖(제외 항목)이라 아직 없다.
- 소형 공연장(첫 투어) 이후 단콘~월클 콘서트 5곳은 사용자 요청으로 추가했다. 필요 팬은 현재 성장 속도로는 매우 먼 목표지만, 계속 키워 나가는 게임이라는 사용자 방침에 따라 그대로 두었다. 팬 조건·보상은 `balance.ts`의 `STAGES`에서 조정한다.
- 콘텐츠 팩 2: 서버가 보유량을 검증하지 않아(저장 JSON을 그대로 보관) 조작된 저장의 포토카드 교환·점수는 막지 못한다. 챌린지·차트·교환소는 서버 로직을 가짜 모델로 확인했고 실제 MongoDB·로그인 상태의 브라우저 화면은 이 환경에서 확인하지 못했다. 마스코트의 배경음악 레이어는 합성 BGM 구조를 바꿔야 해서 뺐다(쓰다듬기 효과음만). 샘플러 녹음은 마이크 권한과 MediaRecorder가 필요하다.
- 로컬 저장이라 기기 시계 변경을 막지 못한다. 음수 시간·비정상 수치는 방어하지만 온라인 랭킹에는 쓸 수 없다.
- 탭 잠금은 같은 브라우저 프로필 안에서만 동작한다. 다른 브라우저·기기와는 동기화되지 않는다.
- 작업실은 코드로 그린 임시 SVG(캐릭터는 첨부 이미지), 효과음은 Web Audio 합성음이다. 배경음악은 사용자가 지정한 두 곡을 자아별로 재생한다(첫 입력 후 시작, 자아 전환 시 교차 페이드, 직접 공연 중 볼륨 낮춤, 탭 숨김 시 정지, 설정에서 따로 끌 수 있음). mp3가 약 18MB라 첫 로드가 무겁고, 곡의 사용 권리는 사용자 몫이다. 실제 일러스트는 없다.
- 실제 모바일 기기 터치와 사람 손으로 한 리듬 입력은 에뮬레이션·자동 입력으로만 확인했다. 오디오 출력은 이 환경에서 들어보지 못했다.
