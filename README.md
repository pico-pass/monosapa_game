# 모노사파 키우기 — 두 자아의 믹스테이프

듀얼 자아 방치형 음악 성장 게임. 클릭으로 작업을 돕고, 일반·어둠 두 자아로 곡을 만들고, 앨범과 공연으로 성장한다.
기획서(`monosapa_game_design.md`) 기준 MVP 전체(14장 1~4단계)를 구현한 웹게임이다. 게임 규칙은 모두 클라이언트에 있고, 서버(NestJS + MongoDB)에는 구글 로그인, 계정별 저장, 계정 레벨 랭킹, 공개 챗방, 문의함이 있다.

> 게임 속 가상의 설정·대사·댓글이며 실제 인물의 건강 상태나 성격, 발언을 나타내지 않는다. 일반속성 싱글 제목은 제작자가 지정한 목록(`frontend/src/game/content.ts`의 `SINGLE_TITLES.normal`)을 순서대로 쓴다. 곡 발매는 게임 안의 연출이고 실제 음원은 만들어지지 않는다.

## 구조와 실행

npm workspaces 모노레포다.

```text
frontend/   React + TypeScript + Vite 게임 클라이언트 (게임 규칙·UI·테스트·시뮬레이션 전부)
backend/    NestJS + TypeScript 서버 (health, 구글 로그인 auth, 계정 users, MongoDB 연결 database). 게임은 아직 서버에 저장하지 않는다. 기능별 모듈 구조: src/{health,users,auth}/{*.module,*.controller,*.service,*.schema,dto/}, src/database, src/config/{app.config,config.module}.ts, src/app.module.ts, src/main.ts
```

```bash
npm install          # 루트에서 한 번
npm run dev          # 게임 http://localhost:5173 (백엔드 없이도 동작)
npm run dev:backend  # (선택) NestJS http://localhost:3000/api/health
npm test             # 자동 테스트 279개 (엔진·저장·미니게임·새 기능·콘텐츠 팩 2·화면 렌더링)
npm run typecheck
npm run build        # frontend/dist, backend/dist
npm run sim          # 성장 속도 시뮬레이션
```

Node 22 + npm 11에서 확인했다. 게임은 외부 API·원곡·로그인 없이 동작하며 저장은 브라우저 localStorage다. 개발 서버의 `/api` 요청은 backend(3000)로 프록시된다.

### 구글 로그인 + MongoDB 설정

로그인은 설정 창(⚙)의 「계정」에 나온다. 서버에 `GOOGLE_CLIENT_ID`가 없거나 서버에 닿지 않으면 계정 영역은 아예 숨겨지고 게임은 그대로 동작한다.

1. Google Cloud Console → API 및 서비스 → 사용자 인증 정보 → **OAuth 클라이언트 ID(웹 애플리케이션)** 를 만들고, *승인된 JavaScript 원본*에 `https://monogame69.net`(개발은 `http://localhost:5173`)을 넣는다. 리디렉션 URI는 필요 없다(ID 토큰 방식).
2. 서버에 MongoDB를 준비하고(로컬 mongod 또는 Atlas) pm2 환경에 넣는다:

```bash
MONGODB_URI='mongodb://127.0.0.1:27017/monosapa' GOOGLE_CLIENT_ID='<클라이언트 ID>' pm2 restart monosapa-backend --update-env && pm2 save
```

- DB에는 `users`(구글 `sub` 유니크, 이메일·이름·사진), `sessions`(토큰 SHA-256 해시, 만료되면 TTL 인덱스가 삭제), `saves`(계정별 게임 저장), `chat_messages`(챗방, 14일 TTL), `inquiries`(문의와 답변) 컬렉션이 생긴다.
- **관리자**: 서버 환경 변수 `ADMIN_EMAILS`(쉼표로 구분, 구글에서 확인된 이메일과 비교)에 든 계정이 문의 답변과 챗방 메시지 삭제를 할 수 있다. 비어 있으면 관리자가 없다. `backend/.env`에 `ADMIN_EMAILS=내이메일@example.com`을 넣고 `pm2 restart monosapa-backend --update-env`.
- 로그인 요청은 클라이언트 ID(aud)·서명·만료가 맞는 구글 ID 토큰만 받는다. 세션 쿠키는 HttpOnly·SameSite=Lax이고 nginx 뒤 https에서는 Secure다(`trust proxy`).
- 검증 방법: 메모리 MongoDB(실제 mongod 8.2)로 로그인·재로그인·만료·위조 쿠키·로그아웃 등 22개 시나리오를 HTTP로 확인했다(구글 검증만 대역). 화면은 브라우저에서 직접 확인하지 못했다.

### 배포 (nginx + pm2)

```bash
./deploy.sh              # 테스트 → 빌드 → 백업 → 웹 루트 교체 → (백엔드가 바뀌었으면) pm2 재시작 → 검증
./deploy.sh --dry-run    # 빌드만 하고 바뀔 파일을 보여 준다 (서버는 건드리지 않는다)
./deploy.sh rollback     # 프런트를 가장 최근 백업으로 되돌린다
```

- 프런트(`frontend/dist`)는 nginx 웹 루트 `/var/www/monosapa`에 `assets/` 먼저, `index.html` 마지막 순서로 올린다. 내용(체크섬)이 같은 파일은 다시 복사하지 않는다. 교체 전 `~/deploy-backup/monosapa-<시각>`에 백업하고 최근 10개만 남긴다.
- 백엔드는 `backend/dist`가 바뀌었거나 pm2 프로세스(`monosapa-backend`)가 꺼져 있을 때만 `pm2 restart` 후 `pm2 save`한다. 서버에 저장 상태가 없어 재시작해도 잃는 것은 없다.
- 마지막에 `https://monogame69.net`이 새 번들을 서비스하는지와 `/api/health`를 확인하고, 실패하면 롤백 명령을 안내하며 종료 코드 1로 끝난다.
- nginx 설정(SSL·`/api` 프록시)은 스크립트가 관리하지 않는다. `rollback`은 프런트만 되돌리고 백엔드는 되돌리지 않는다. 커밋하지 않은 변경도 작업 폴더 그대로 배포되므로 경고만 띄운다. 경로·도메인·프로세스 이름은 환경 변수(`WEB_ROOT`, `DOMAIN`, `PM2_NAME`, `BACKUP_ROOT`, `KEEP_BACKUPS`)로 바꾼다.

> 참고: backend의 Nest CLI 의존성 일부가 Node ≥ 22.22를 요구해 Node 22.15에서는 설치 시 EBADENGINE 경고가 나온다(빌드·실행은 정상).

## 구현한 것

- **두 자아**: 일반/어둠 전환(무료, 3초 재전환 잠금), 과열 G 0~100, 80 이상 고속 구간, G=100 「마이크 압수」(일반 자동 전환, 20초 생산 50%, 재진입은 20초 경과 + G≤60). 재화는 잃지 않는다.
- **생산·수입**: 자동 라임(일반/어둠 별도 보관), 작업하기 패드(터치·마우스·키보드 합산 초당 3회 상한, 누르고 있으면 초당 2회), 팬 기반 인세, 레벨.
- **싱글·앨범**: 제목 미리보기·필요 라임·보상 표시, 즉시 발매, 가상 댓글. 앨범은 싱글을 고르는 방식이 아니라 **정해진 묶음(`ALBUM_CATALOG`)을 위에서부터 차례로 발매**한다: ① [SAPA] EP(5곡) → ② [MONO] EP(5곡, 타이틀 「이리 와」) → ③ [cybergirl.vst3] 싱글(3곡, 타이틀 「cybergirl.vst3」). 비용 10,000 → 350,000 → 20,000,000코인, 팬 +100 → +200 → +300(사용자 지정 값, `balance.ts`의 `album`), 발매 시 인세 배율 +8% → +10% → +12%(누적 합산, 3장이면 ×1.30). 듀얼 앨범 기능은 없앴다. 3장을 모두 내면 더 낼 수 없고, 도감에 수록곡과 함께 보관된다.
- **장비 3종**(마이크·작업실·홍보, 최대 20레벨): 구매 전·후 생산/수입 표시, 작업실 5레벨마다 방 외형 변화. **장비는 속성마다 따로 있고(사용자 지정) 그 속성일 때만 효과가 난다.** 장비 탭에서 「일반속성 장비 / 어둠속성 장비」를 전환해 산다. 레벨당 효과는 같고, 어둠 장비는 최초 비용이 일반의 12배, 가격이 늘어나는 폭(성장률 − 1)이 일반의 2.4배다. 방 외형 단계는 지금 자아의 작업실 레벨을 따른다.
- **클릭 업그레이드**(장비 탭, 사용자 요청으로 추가): 코인으로 올리며 **레벨당 작업하기 한 번에 얻는 기본 라임 +1**(그 속성의 생산배율이 곱해진다). 일반속성은 **순수 음악력**(비용 `ceil(250×1.5^레벨)`: 250 → 375 → 563 …), 어둠속성은 **음지 드립력**(비용 `ceil(3000×2.2^레벨)`)이고 각자 자기 속성에서만 효과가 난다. 최대 레벨은 없고 자동 생산(초당 라임)에는 영향이 없다. 값은 `balance.ts`의 `musicPower`·`dripPower`. 예전 저장에는 이 필드들이 없어 0레벨로 읽는다.
- **공연 8곳(+비밀 공연장 3곳)**(방구석 → 지하 클럽 → 소형 공연장 → 단콘 → 중형 공연장 → 중대형 공연장 → 대형 콘서트 → 월클 콘서트): 팬 조건 + 이전 공연장 클리어로 해금, 자동 공연(1배, 클리어 인정), 직접 공연(방구석은 마이크 타이밍, 지하 클럽은 모노사파런), 공연장별 120초 쿨다운, 첫 클리어 보너스 1회, 소형 공연장 첫 클리어 시 「첫 투어 완료」 카드(그 뒤 5곳은 확장 콘텐츠). 새 5곳 수치는 팬 3,000/8,000/20,000/50,000/150,000명, 기본 코인 300/600/1,200/2,500/6,000, 첫 클리어 보너스 3,000/7,500/18,000/45,000/120,000(`STAGES`). 직접 공연 난이도는 월클 콘서트가 ×2.53.
- **모노사파런(지하 클럽의 직접 공연)**: 달리면서 점점 빨라지는 러너. 탭·스페이스·↑로 점프(공중에서 한 번 더), 장애물(스피커 박스)에 부딪히면 하트 3개 중 1개를 잃고 1.2초 무적(그동안 속도 ×0.7), 하트가 0이 되면 실패. **완주하면 성공**, 점수(0~1000)는 코스에 깔린 젤리 중 먹은 비율이고 보상 공식은 타이밍과 같다(`기본 코인×(1+점수/1000)×자아 배율`, 실패는 ×0.5·첫 클리어 아님). **일반 2,600m / 어둠 6,900m**, 어둠은 더 빠르고 더 길며 **보상이 일반의 4배**(`run.persona.dark.rewardMult`). 속도는 달린 거리에 비례해 일반 8→16, 어둠 11→22(u/s)로 선형 증가하고 장애물 간격은 반응 시간(초) 기준이라 뒤로 갈수록 촘촘해진다. 스크롤 단위(u)로 규칙을 돌리고 화면의 m는 코스 길이에 비례해 환산한다(일반 1,500u=2,600m, 어둠 2,400u=6,900m). 코스는 시드 난수로 만들어 같은 시드면 같은 코스, 규칙은 `game/runner.ts`(React 비의존)에 있고 화면은 `screens/RunStage.tsx`. 알맞게 점프하는 자동 플레이어 기준 완주 약 130초(일반)/151초(어둠), 젤리 약 73~85%. 직접 공연 중 탭을 숨기면 일시정지한다.
- **미니게임 마이크 타이밍(방구석)**: 10개 과제, 첫 목표 1초·첫 간격 2초에서 시작해 **과제 간격이 ×1.08씩 줄어든다**(`paceGrowth`, 마지막 간격 약 1.08초, 공연 길이 약 15.5초). 접근 링과 박자음도 같은 템포로 빨라져 화면에서 속도가 붙는 게 보인다. 입력 구간은 최대 ±500ms이며 간격의 절반을 넘지 않는다, 기본 판정 폭(난이도 1) 일반 ±120/±300ms · 어둠 ±120/±220ms를 **공연장 난이도로 나눈다**: 방구석 ×1.30 → 지하 클럽 ×1.43 → 소형 공연장 ×1.57(`baseDifficulty` 1.3, 공연장마다 ×1.1). 예) 방구석 일반 Perfect ±92/Good ±231ms, 소형 공연장 일반 Perfect ±76/Good ±191ms. 난이도는 공연 시작 때 고정되고 보상 공식은 그대로. 한 공연 안에서도 과제를 넘길 때마다 난이도가 쌓인다(`stageTaskGrowth`로 공연장별: **방구석 ×1.33**, 나머지 `taskDifficultyGrowth` ×1.25). 방구석 10번째 과제는 약 ×13배: 일반 기준 1번째 Perfect ±92/Good ±231ms → 10번째 ±7/±17ms. 난이도·판정 폭 수치는 화면에 표시하지 않는다. 어둠 자아는 판정이 더 좁은 대신 직접 공연 보상 ×1.5(`personaRewardMult.dark`, 원안 1.15). 600점 이상 클리어, 탭 숨김 시 일시정지, 소리 없이도 가능.
- **콘텐츠**: 자아×8상황 대사 80개(원래 톤/순화 톤), 자아별 곡 제목·앨범 제목 템플릿, 가상 댓글, 자아 전환 시 캐릭터·조명·포스터·말풍선 모양 변화.
- **저장·복구**: localStorage 5초 자동 저장 + 중요 행동 직후·탭 숨김·종료 시 저장, 이를 구글 계정별로 MongoDB에 자동 동기화(진행 데이터는 계정에만 있다. 파일 내보내기·불러오기·초기화 버튼은 없다), 스키마 검증, 정상 저장 백업, 손상 시 백업 복구/새 게임 선택(손상 원본은 별도 키에 보관). Web Locks(없으면 BroadcastChannel)로 쓰기 탭 1개만 허용하고 두 번째 탭은 읽기 전용 안내 + 「이 탭에서 계속하기」.
- **방치 보상**: 최대 2시간, 효율 70%, 과열 80·100·압수 구간 경계 정확 계산, 복귀 시 1회 자동 반영(결과창은 「확인」만), 탭 숨김 복귀도 같은 엔진으로 1회 정산.
- **다이아 재화**(사용자 요청으로 추가, 상단바에 💎 표시). 수량은 모두 제안값이고 `balance.ts`의 `diamond`·`STAGES[].firstClearDiamonds`에서 조정한다.
  - 획득: **공연장 첫 클리어**(방구석 5 · 지하 클럽 10 · 소형 15 · 단콘 20 · 중형 30 · 중대형 40 · 대형 50 · 월클 80, 합계 250), **앨범 발매**(30 · 60 · 120), **플레이어 레벨이 1 오를 때마다 2**(싱글·앨범으로 팬이 늘어 오를 때).
  - 사용: **공연 쿨다운 즉시 초기화**(5, 공연 탭), **마이크 압수 즉시 해제**(10, 압수 중 작업실 탭: 생산 패널티 해제 + 과열 0 + 어둠 재진입 조건 해소), **다이아 전용 영구 업그레이드**(장비 탭 아래, 최대 20레벨, 레벨당 +5%): 생산 증폭(자동 생산과 작업하기 라임, 일반·어둠 모두)과 인세 증폭. 비용은 `ceil(5×1.25^레벨)` 다이아.
  - 다이아가 없던 예전 저장은 처음 불러올 때 **이미 클리어한 공연장·이미 낸 앨범·이미 오른 레벨만큼 한 번 소급 지급**한다(`retroactiveDiamonds`). 새 필드가 있는 저장은 소급하지 않는다. 오프라인 정산·직접 공연 점수에는 영향이 없다.

  - 팬이 있으면 **팬 1명당 초당 0.2**(초당 팬 수 × 0.2)만큼 스트리밍이 실제 경과 시간에 따라 쌓인다(자아·장비·과열과 무관, 오프라인은 다른 생산처럼 효율 70%·최대 2시간). 쌓인 스트리밍은 **Spotify · YT Music · Melon · Apple Music**에 무작위로 나뉘어 플랫폼별로 기록된다. 화면에는 K·M 약어나 소수 없이 **1회 단위 정수**로 표시한다(`components/format.ts`의 `fmtStreams`, 초당 값이 1 미만이면 '1 미만').
  - 분배는 10분 구간마다 새로 뽑는 무작위 비율이고(`shareBucketMs`), 저장된 씨앗과 구간 번호만으로 정해지는 시드 난수라 엔진은 순수 함수로 남는다. 한 번에 크게 전진해도(오프라인 정산) 여러 번 나눠 전진해도(온라인 틱) 플랫폼별 결과가 같다. 구간마다는 크게 쏠리기도 하지만 오래 쌓이면 각 플랫폼이 25%에 가까워진다.
  - **1시간마다 코인으로 정산**할 수 있다(통계 탭 버튼, **30스트리밍 = 1코인**). 30으로 나누고 남은 스트리밍은 다음 정산으로 넘어가고, 정산하지 않아도 사라지지 않는다. 누적 기록은 정산해도 줄지 않는다. 첫 정산은 새 게임 시작 후 1시간 뒤다.
  - 스트리밍이 없던 예전 저장은 0에서 시작하고 첫 정산은 바로 가능하다(복귀 정산분만 쌓여 있다). 기기 시계가 거꾸로 가도 정산 간격은 1시간보다 길어지지 않는다.
- **화면**: 모바일 세로 우선(360px 확인), 버튼 최소 44px, 모션 감소, 캐릭터 이미지 2종(frontend/public/assets, 없으면 임시 SVG로 대체)·임시 SVG 작업실, 선택 음향(첫 입력 후에만 켜짐, 음소거 설정).

### 성장 속도 시뮬레이션 (`npm run sim`)

게임 엔진·명령을 그대로 호출하는 봇이 1초 단위로 플레이한다(발매 가능하면 즉시 발매, 앨범·장비 중 가장 싼 것부터 구매, 공연은 자동 공연). 시간은 모두 게임 시간이다.

| 경로 | 첫 발매 | 첫 앨범 | 방구석 | 지하 클럽 | 첫 투어 완료 |
| --- | --- | --- | --- | --- | --- |

- **스트리밍 정산을 넣은 뒤의 수치다(괄호는 정산 없이 돌린 이전 값, `npm run sim -- --no-streaming`).** 봇은 정산 간격(1시간)이 지나는 즉시 정산한다. 첫 앨범은 약 5~8% 앞당겨졌고(예: 클릭 2회/초·혼합 253분 → 237분, 팬당 초당 0.85였을 때는 14~26%), 첫 발매·방구석처럼 1시간 안에 끝나는 구간은 거의 그대로다. 스트리밍은 팬 수에 비례해 쌓이므로 팬이 많아질수록 비중이 커진다: 처음 지정값(3스트리밍 = 1코인)은 팬당 초당 0.283코인으로 인세의 11배라 30으로 바꿨고, 이후 팬당 초당 스트리밍을 0.85에서 0.2로 낮춰 지금은 팬 1명당 초당 약 0.0067코인(= 0.2 ÷ 30)으로 인세 기본치(팬당 초당 0.025)의 약 27%다.
- **장비를 속성별로 나눈 뒤의 수치다.** 일반 장비는 일반속성에서만, 어둠 장비는 어둠속성에서만 효과가 나고 어둠 장비는 가격이 12배·성장 폭이 2.4배라 어둠을 쓰는 경로는 첫 앨범·지하 클럽이 늦어졌다. 일반만 쓰는 경로는 그대로다. 봇은 어둠을 쓰는 전략일 때 어둠 장비도 가장 싼 것부터 사지만, 순수 음악력과 음지 드립력은 사지 않는다.
- 싱글 공식을 `ceil(130×3.3^n)` / `floor(50×1.44^n)` / `ceil(5×1.8^n)`으로 바꾼 뒤의 결과다. 싱글 비용이 곡마다 3.3배씩 뛰어 6시간 동안 6~12곡에서 멈추고, 앨범은 지정한 3장뿐이고 팬 +100/+200/+300은 비싼 코인(1만/35만/2천만)이 필요해서, 앨범은 초반 지름길이 아니라 중후반 코인 소비처다. 팬 대부분은 싱글에서 나온다.
- **투어 완료 시간은 더 이상 목표가 아니다.** 사용자 결정으로 이 게임은 "첫 투어를 빨리 끝내는 것"이 아니라 계속 키워 나가는 게임이다(기획서의 1~2시간 투어·「일반만으로도 모든 기본 지역 개방」 목표는 접었다). 위 표는 현재 수치의 참고용이다. 첫 앨범(10,000코인)은 방치로 3시간대에 낼 수 있다.
- **싱글 비용·효과는 자아별로 따로 센다**(n은 그 자아로 낸 싱글 수). 어둠을 함께 쓰면 두 줄의 곡선을 동시에 타서 첫 발매는 빨라지지만, 어둠 장비가 비싸고 일반 장비는 어둠에서 효과가 없어서 이후에는 일반만 쓸 때보다 느려질 수 있다.
- 이 봇은 구매·발매를 놓치지 않는 이상적인 플레이어라서, 실제 플레이는 이보다 느릴 수 있다.

## 모호한 규칙에 내린 작은 결정

- **시각 체계**: 모든 시각은 `Date.now()` 기준 ms. 엔진의 "지금"은 `state.lastSettledAt`이고, 명령은 매번 정산 후 실행한다.
- **마이크 압수 잠금**: 별도 잠금 타이머 없이 「20초 경과 + G≤60」 재진입 조건 자체가 잠금이다. 이 조건은 어둠 재진입에 성공하면 해소된다. 압수 직후 일반으로 돌아가는 것은 막지 않는다(이미 일반).
- **어둠 수동 전환**: G≤80(80 포함)이면 허용. 압수 후 재진입은 G≤60.
- **오프라인 2시간 초과분**: 앞쪽 2시간만 효율 70%로 지급하고, 나머지 시간은 지급 없이 과열 회복·잠금만 실시간 100%로 흘려보낸다.
- **탭 숨김 복귀**: 숨긴 시간이 짧아도 오프라인 효율(70%)로 한 번 정산한다. 결과창은 30초 이상일 때만 띄운다(보상은 항상 반영). 온라인 틱 간격이 5초를 넘으면(절전 복귀 등) 오프라인으로 본다.
- **입력 상한**: 1초 슬라이딩 창 안에 3회. 누르기 유지는 0.5초 간격(초당 2회). `onClick`을 쓰지 않고 포인터·키 다운만 받아 탭+길게누르기 이중 지급이 없다.
- **싱글 제목**: 자아별 목록에서 결정적으로 고르고(미리보기와 동일), 같은 제목이 다시 나오면 `(2)`를 붙인다. ID는 `single-N`로 제목과 분리.
- **앨범 속성**: 세 앨범 모두 일반이다. 속성(일반/어둠)은 표시에만 쓰고 효과 차이는 없다(`content.ts`의 `ALBUM_CATALOG[].type`). 듀얼 앨범과 팬 ×1.25 보너스는 사용자 요청으로 삭제했다. 앨범은 발매한 싱글과 무관하고, 저장에는 id·발매 시각만 쓰며 제목·속성은 카탈로그에서 읽는다. 예전 저장(싱글 2개 앨범)은 앞에서부터 카탈로그 앨범으로 옮겨 읽고 3장을 넘는 앨범은 버린다.
- **자아별 번호와 비용**: 싱글 번호와 도감 목록은 일반/어둠별로 따로 센다. 싱글 발매 비용·효과(필요 라임·코인·팬)의 n도 자아별이라, 일반을 11곡 낸 뒤 처음 어둠으로 내면 어둠 첫 곡 값(필요 라임 50 등)이다. 두 자아의 성장 곡선은 `frontend/src/game/balance.ts`의 `single.normal`/`single.dark`에서 따로 조정한다. 인세의 앨범 수와 앨범 비용·팬은 발매한 앨범 수 기준이다. 싱글 내부 ID(`single-N`)는 전체 순서이고 앨범 ID는 카탈로그 순서(`album-1~3`)다.
- **공연**: 직접 공연의 600점 미만 보상은 `floor(계산값×0.5)`. 자동 공연은 자아와 무관하게 기본 코인 1배. 직접 공연 시작 시 쿨다운과 공연 자아를 확정하고 즉시 저장한다. 새로고침하면 진행 중 공연은 포기로 처리되며 쿨다운은 유지된다. 시작 전 3초 카운트다운은 미니게임 시계에 포함되지 않는다.
- **불러오기**: 가져온 파일의 `lastSettledAt`은 현재로 맞춘다. 오래된 파일을 반복해서 불러와 오프라인 보상을 다시 받을 수 없다.
- **대사 톤**: 기본은 「원래 톤」. 「순화」는 욕설이 들어간 어둠 대사만 같은 뜻의 순한 말로 바꾼다(수치 동일).
- **자동 말풍선**: 직전 말풍선 이후 15초 미만이면 나오지 않는다. 발매·구매·압수·공연 같은 이벤트 대사는 즉시 우선한다.

## 남은 제약

- 코인은 장비·앨범·간식·홍보 캠페인에 쓰인다. 간식과 캠페인은 가격이 플레이어 레벨에 따라 올라 후반에도 싱크로 남지만, 환생·새 믹스테이프는 기획서 범위 밖(제외 항목)이라 아직 없다.
- 소형 공연장(첫 투어) 이후 단콘~월클 콘서트 5곳은 사용자 요청으로 추가했다. 필요 팬은 현재 성장 속도로는 매우 먼 목표지만, 계속 키워 나가는 게임이라는 사용자 방침에 따라 그대로 두었다. 팬 조건·보상은 `balance.ts`의 `STAGES`에서 조정한다.
- 콘텐츠 팩 2: 서버가 보유량을 검증하지 않아(저장 JSON을 그대로 보관) 조작된 저장의 포토카드 교환·점수는 막지 못한다. 챌린지·차트·교환소는 서버 로직을 가짜 모델로 확인했고 실제 MongoDB·로그인 상태의 브라우저 화면은 이 환경에서 확인하지 못했다. 마스코트의 배경음악 레이어는 합성 BGM 구조를 바꿔야 해서 뺐다(쓰다듬기 효과음만). 샘플러 녹음은 마이크 권한과 MediaRecorder가 필요하다.
- 로컬 저장이라 기기 시계 변경을 막지 못한다. 음수 시간·비정상 수치는 방어하지만 온라인 랭킹에는 쓸 수 없다.
- 탭 잠금은 같은 브라우저 프로필 안에서만 동작한다. 다른 브라우저·기기와는 동기화되지 않는다.
- 작업실은 코드로 그린 임시 SVG(캐릭터는 첨부 이미지), 효과음은 Web Audio 합성음이다. 배경음악은 사용자가 지정한 두 곡을 자아별로 재생한다(첫 입력 후 시작, 자아 전환 시 교차 페이드, 직접 공연 중 볼륨 낮춤, 탭 숨김 시 정지, 설정에서 따로 끌 수 있음). mp3가 약 18MB라 첫 로드가 무겁고, 곡의 사용 권리는 사용자 몫이다. 실제 일러스트는 없다.
- 실제 모바일 기기 터치와 사람 손으로 한 리듬 입력은 에뮬레이션·자동 입력으로만 확인했다. 오디오 출력은 이 환경에서 들어보지 못했다.
